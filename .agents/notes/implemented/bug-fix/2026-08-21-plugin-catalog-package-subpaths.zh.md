# Agent Note：插件目录包子路径

状态：已实现

[English](2026-08-21-plugin-catalog-package-subpaths.md) | 中文

## 问题

npm 目录可以列出 `dsh-builtin-browser`，但精确版本补全会把 `dsh-builtin-browser/browser` 等 Loader 模块名误判为非法包名。因此，即使包和制品实际可用，界面仍会在安装开始前提示暂时无法读取版本详情。

## 决策

目录权威现在会把每个 Loader 模块标识拆分为 npm 包所有者和可选的导出子路径。Bundle 可以挂载自身的合法导出子路径；聚合 Bundle 也可以挂载使用精确版本声明的依赖包子路径，或封闭 Host 已提供包的子路径。空路径段、`.` 与 `..` 路径段、反斜杠、不支持的字符、未声明的包和非精确依赖版本仍会被拒绝。

## 验证

npm 生态目录测试复现了已发布 `dsh-builtin-browser@0.1.15` 的三个 Loader 条目及其 YAML 表达式，并确认精确详情进入可安装状态，同时得到预期的 `browser`、`browser-electron` 和 `tool-browser` 条目。负向用例继续拒绝形似路径穿越的子路径。针对已发布包的实时 npm 冒烟检查也完成了搜索与精确版本补全。

## 考虑过的替代方案

**信任每一个 `name:` 后的字符串。** 未采用，因为聚合包随后可能引用未声明依赖或不安全路径。

**要求发布者把三个子路径拆成三个包。** 未采用，因为 npm 包导出子路径本身就是合法的 Loader 模块标识，而且已发布包已经明确导出了这些入口。

**针对 `dsh-builtin-browser` 写特例。** 未采用，因为缺陷位于模块标识解析；名称特例会在下一个使用合法 exports 的 Bundle 上再次出现。

## 后果

Issue 17 现在可以通过精确详情和安装预检，同时不会削弱压缩包、包身份、依赖或路径校验。本次变更不会安装 Chromium，也不会改变插件的运行时依赖行为；这些检查仍由插件在安装后负责。

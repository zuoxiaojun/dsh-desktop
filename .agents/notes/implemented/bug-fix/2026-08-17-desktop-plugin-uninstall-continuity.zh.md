# Agent Note: 桌面插件卸载连续性

Status: implemented

[English](2026-08-17-desktop-plugin-uninstall-continuity.md) | 中文

## 问题

部分生态 Bundle 会注册运行时 Skill，却没有将它们写入 `dsh.pluginCenter.expectedSkillIds`。停用或卸载这类 Bundle 时，其 Loader 条目和运行时 Skill 会被正确移除，但连续性校验器无法把未声明的 Skill 归属给目标插件，于是将其误判为无关 Skill 丢失、回滚事务并恢复软件包，最终表现为插件刷新后重新出现。Host 成功换代时还会把 BrowserWindow 导航到新的回环来源，短暂暴露空白的中间 renderer。虽然插件中心主页面能够恢复，但展开的已安装管理器此前只存在于组件内存中，renderer 重新挂载后就会收起。

## 决策

停用和卸载继续严格核对目标已声明身份、`agent-presets` 所有者条目、每个无关且跨重启稳定的 Loader 条目，以及每个无关客户端模块。只对这两类去激活动作，Skill 连续性改为兼容证据而非回滚边界：目标 Loader 身份消失后，如果某个 Skill 没有出现在任一受影响候选版本的 `expectedSkillIds` 中，就允许它一起消失。激活和更新继续沿用原有的严格证据规则。

Host 重连时，桌面端会在真实 renderer 导航期间，用一个沙箱化、只驻留内存的 `WebContentsView` 保留 BrowserWindow 最后一帧。数据文档加载完成后才挂载保留帧，并在替换 renderer 完成绘制或短暂上限到达后释放。截图、等待绘制和释放失败只记录诊断；权威导航失败仍会让变更链路失败。已安装管理器会把展开状态写入一个固定 renderer URL 参数。替换 URL 只在返回插件中心时迁移这一项确定值，并丢弃全部任意查询参数，因此新的 renderer 会重新挂载同一子页面，又不会把 renderer 状态变成导航权威。

## 验证

运行时校验器单元测试覆盖目标未声明 Skill 消失，同时保留无关 Loader、客户端和 Skill 证据。已安装插件管理集成 fixture 会注册一个未声明运行时 Skill，并证明卸载能够提交而非恢复 Profile。保留帧切换单元测试固定了执行顺序、尽力而为的截图与绘制等待、释放，以及导航失败的向上传播。客户端覆盖证明已安装管理器会从 URL 标记恢复并同步开关；Desktop URL 覆盖证明预期返回插件中心时会保留该标记，而无关参数和其他主页面不会继承它。

## 考虑过的替代方案

**要求全部既有生态包先发布 `expectedSkillIds` 才允许卸载。** 否决，因为卸载事务被阻止时，已经安装的软件包无法自行修正 manifest。

**取消卸载后的运行时校验。** 否决，因为 Profile 投影、目标 Loader 移除，以及无关 Loader 和客户端连续性仍是防止变更损坏的有效保护。

**每次 Host 成功换代都展示加载页或恢复页。** 否决，因为用户仍停留在同一个插件中心流程时，这会把内部重启暴露为整窗状态切换。

## 后果

Skill 元数据不完整的插件现在可以停用和卸载，不再发生错误回滚；已声明身份以及更强的 Loader 与客户端连续性仍会保护事务。同一次去激活过程中，如果另一个未声明 Skill 意外消失，由于无法独立确认归属，它将不再单独触发回滚；完整声明 Skill 的软件包仍接受精确校验。Host 导航期间，桌面端会短暂持有一张内存截图和一个沙箱子 WebContents，并在替换页面绘制后释放。已安装管理器选择会显示在本地回环 URL 中并跨受控 Host 换代保留，但不会新增历史记录，也不携带任何变更权威。

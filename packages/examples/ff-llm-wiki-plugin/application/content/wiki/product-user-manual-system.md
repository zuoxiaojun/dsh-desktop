# 用户操作手册体系

> 面向用户的功能说明与自助答疑的操作路径体系。

## 结论

手册保证每个功能操作路径唯一可复现，并把高频问题沉淀为自助条目。

它与客服话术共享术语，是客服知识库的产品侧源头。

## 来源证据

- **用户操作手册（v2.3）**（`raw/product-manual.md` · 产品部）
  - 每个功能的操作路径必须唯一且可复现，避免多入口造成认知负担。
  - 常见问题（FAQ）要沉淀为可检索条目，减少重复人工答疑。
  - 用户反馈应回流到需求池，形成「使用 → 反馈 → 迭代」闭环。
  - 手册与产品承诺的服务水平保持一致，承诺能力必须可自助验证。
- **客服话术手册（常见问题处理）**（`raw/support-script.md` · 客服部）
  - 高频问题必须沉淀为标准话术，答复口径全团队统一。
  - 话术以产品操作手册为上游依据，偏差即产品缺陷。
  - 首次响应必须在约定时限内给出，不能「已记录」了之。
  - 疑难问题按升级标准转交，不在一线反复空转。

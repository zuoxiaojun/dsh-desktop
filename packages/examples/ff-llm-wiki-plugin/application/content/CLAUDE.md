# 编译规则层（CLAUDE.md）

本文件是 LLM Wiki 编译器的 schema 约定。编译器每次 Ingest（编译）前必须先读本文件，
再据此生成产物层 `wiki/`。

## 页面类型（type）

- `concept`：概念页——解释一个跨来源的知识概念，回答「是什么 / 为什么」。
- `system`：系统页——描述一个可运行或可设计的系统、体系或平台。
- `playbook`：手册页——可执行的流程、步骤或应急预案。
- `policy`：策略页——约束与决策规则。

## 命名约定（slug）

- 稳定 slug 用短横线（kebab-case），如 `product-lifecycle`。
- 一旦确立不得随意变更，否则互链断裂、无法治理。
- slug 与源文件名不一一对应：一个知识单元可聚合多份源资料。

## wikilink 语法红线

- 跨页引用必须写带目录前缀的 `[[wiki/<slug>]]`，禁止裸 `[[<slug>]]`。
- 目录前缀统一为 `wiki/`，带别名时可写 `[[wiki/<slug>|<显示名>]]`。
- 裸 slug 在抽边模式下建 0 条边，会静默少边。

## 三层结构

1. 规则层：本文件（人类撰写 schema）。
2. 源层 `raw/`：源真相，只读——编译与查询绝不修改、绝不新增文件。
3. 产物层 `wiki/`：编译产出的互链知识页，机器可再生。

## 编译产物形态标准

- 页按知识单元划分，不与源文件 1:1 对应（跨源重组）。
- 每页 = frontmatter（title / type / slug / sources / updated）+ 结论性正文 + 来源证据 + 互链。
- `sources` 回指来源文件；正文是综合结论，不是逐字抄写源文。
- 每次编译更新 `index.md`（导航）与 `log.md`（变更日志）与 `manifest.json`（机器可读）。
